# Zero-Cost YouTube Shorts Factory

A Python 3.11+ pipeline for producing original, vertical educational videos from a curated topic bank, local text-to-speech, procedural artwork, word-highlighted captions, and FFmpeg. GitHub Actions can run it once a day and, after you explicitly configure Google OAuth and enable uploads, publish at most one new Short per local calendar date through the official YouTube Data API.

**This repository does not promise views, subscribers, monetization approval, or revenue.** YouTube may reject channels whose videos are repetitive, mass-produced, reused, or otherwise fail its monetization policies. Review every new format and the facts before relying on automated public publishing.

## What is automated—and what is not

Automated: choose an unused curated topic; check source metadata and script similarity; produce narration locally; draw original graphics; generate synchronized ASS/SRT captions; render H.264/AAC MP4; validate codec, dimensions, duration and size; optionally upload through OAuth; record the confirmed video ID; snapshot available views and likes.

Manual owner actions: create a GitHub repository, create/configure a Google Cloud project and OAuth client, consent to channel access, store secrets in GitHub, review the generated video and citations, deal with Google consent/verification gates, expand the finite topic bank, and decide whether the channel is ready for public publishing. The script's source check verifies HTTPS URLs and an allow-list of trusted domains. **It does not fetch or independently prove the linked facts.** Review source pages and claims editorially; the repository stops when the reviewed topic bank is exhausted rather than recycling topics.

## Cost model and limitations

| Component | Expected cost | Important limitation |
|---|---:|---|
| Public GitHub repository + standard GitHub-hosted runner | $0 for eligible standard runner usage | GitHub may delay/skip scheduled runs; schedules are not a guaranteed clock. Private repository minutes are subject to included allowances and possible overage charges. |
| Python, Pillow, FFmpeg, espeak-ng, DejaVu font package | $0 | Software is installed at runtime; upstream version availability and licensing can change. |
| YouTube Data API v3 | No per-call bill under ordinary quota allocation | Daily quota, project verification and channel/API restrictions still apply. |
| Google OAuth | $0 | Consent screen/app status and refresh-token expiry can prevent uploads until the owner fixes configuration. |
| Online AI, stock assets, music, storage, VM | Not used | The default pipeline makes no paid AI or asset API calls and uses no external storage/database. |

A free runner does not guarantee unlimited compute, uptime, third-party service access, or API quota. This design intentionally omits background music: clear narration plus original visuals avoids an unnecessary music-rights dependency. The default TTS voice is utilitarian rather than studio-quality.

## Architecture

1. `.github/workflows/daily-shorts.yml` invokes a scheduled or manually dispatched job on Ubuntu.
2. `topic_engine.py` selects from `config/topics.json`; `fact_checker.py` requires each topic to include HTTPS references on the allow-list.
3. `script_writer.py` assembles structured narration and metadata; `originality.py` rejects used topics, exact fingerprints and highly similar scripts.
4. `narration.py` calls local `espeak-ng` (or `espeak` for local development) beat by beat and recalibrates speaking rate up to twice toward a 56-second target when the measured audio is too short or long. `visuals.py` draws each 1080×1920 slide using Pillow; no remote artwork is downloaded.
5. The storyboard uses short 10-frame crossfades between visual scenes. `captions.py` writes word-highlighted ASS captions and an SRT sidecar. Timings are estimated from the exact spoken text and measured TTS segment lengths; they are not generated by a forced-alignment model. Inspect synchronization before public use.
6. `renderer.py` uses FFmpeg to render 30 FPS H.264 + AAC MP4. `validator.py` rejects files outside the configured 50–60-second, vertical-size, codec and file-size requirements.
7. If `DAILY_UPLOAD_ENABLED=true` and `DRY_RUN=false`, `youtube_auth.py` refreshes OAuth credentials and `youtube_upload.py` makes a resumable API upload. Date and topic markers in descriptions let reruns recover an upload whose response or state commit was lost; recent channel history is also reconciled to reduce duplicates if a Git push failed.
8. A confirmed video ID is recorded in `data/history.json`, committed by Actions and reused on future runs. `analytics.py` snapshots views/likes that the YouTube Data API exposes; it does not claim to retrieve revenue or retention.

The bundled topic bank currently contains 36 curated entries. `config/topics.json` is a small manifest that points to the compressed 36-topic bank, transported as base64 chunks under `config/topic_bank/` and decoded locally at runtime. It is finite and intentionally fails closed after all eligible topics have been used. Add and source-review more topics to keep the daily process running. Changing title colours or rephrasing a script is not treated as acceptable new content.

## 1. Create the GitHub repository

1. Create a new repository named `youtube-shorts-factory` and push these files to its default branch.
2. **Recommended for $0 standard hosted-runner use:** make the repository public if you are comfortable making the code and curated topic bank public. Never commit OAuth files, refresh tokens, `.env`, or channel credentials. The workflow secrets are separate from repository contents, but secret storage is not a reason to run untrusted code in a privileged workflow.
3. A private repository has better code visibility control, but GitHub Actions usage is subject to its plan's included minutes/storage and possible overage. Review current billing before choosing private.
4. Keep the scheduled workflow on the default branch. In GitHub, restrict who can change workflow files; do not run untrusted pull-request code with publishing secrets. The provided workflow uses `contents: write` solely to persist `data/history.json`.

## 2. Install prerequisites locally (recommended before Actions)

Python 3.11 or newer, FFmpeg (including `ffprobe` and the `subtitles`/libass filter), espeak-ng, and a readable Sans font are required. Example Debian/Ubuntu commands:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg espeak-ng fonts-dejavu-core python3-venv
python -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
python scripts/validate_environment.py
python -m pytest
```

On macOS, install FFmpeg and espeak-ng with your preferred package manager. Windows can work if `ffmpeg`, `ffprobe`, and `espeak-ng` are on `PATH`, but the Actions runner is the reference environment. Do not put real credentials in `.env.example`.

Generate a local preview without upload:

```bash
python -m shorts_factory --dry-run
```

The MP4 and review materials are written under `build/output/YYYY-MM-DD/`. `short.mp4`, `captions.srt`, `captions.ass`, and `manifest.json` can be reviewed together. `manifest.json` contains the selected topic, script, URLs, claim metadata, and validation report.

## 3. Configure the YouTube Data API

Do this as the channel owner. The workflow cannot create or consent to credentials for you.

1. Open the [Google Cloud Console](https://console.cloud.google.com/), create/select a project, and enable **YouTube Data API v3** in APIs & Services → Library.
2. Configure the OAuth consent screen (branding, audience, support/contact information, and test users if the app is in testing). Choose the application type **Desktop app** when creating the OAuth client for the local authorization script. Download the client JSON to your own computer; do not place it in the repository.
3. Review Google's current [OAuth consent-screen publishing guidance](https://developers.google.com/identity/protocols/oauth2) and the [YouTube Data API getting-started guide](https://developers.google.com/youtube/v3/getting-started). Use the required consent process. This repository does not bypass verification or API restrictions.
4. Install the package locally, then run the consent flow from a desktop terminal with a browser:

   ```bash
   python scripts/authorize_youtube.py ~/Downloads/client_secret_YOUR_ID.json
   ```

5. Sign into the intended Google/YouTube account, review the requested YouTube upload and read-only channel permissions, and approve. The script prints the refresh token **only in your local terminal**. Copy it directly to the matching GitHub Actions secret. Never share terminal screenshots or paste the token into issues/logs.

**OAuth gotcha:** when an External OAuth consent screen remains in **Testing**, refresh tokens for scopes beyond basic identity can expire after seven days. That makes unattended daily publishing unsuitable until the owner configures the consent screen/app status appropriately. Depending on Google's current verification rules and project status, the app may require verification; unverified projects can face private-only upload restrictions. Check Google's current messages and documentation rather than trying to work around them.

Official references: [OAuth 2.0 for installed apps](https://developers.google.com/identity/protocols/oauth2/native-app), [OAuth consent screen](https://support.google.com/cloud/answer/10311615), [YouTube videos.insert](https://developers.google.com/youtube/v3/docs/videos/insert), and [YouTube API quota costs](https://developers.google.com/youtube/v3/determine_quota_cost).

## 4. Add GitHub Secrets and Variables

Open repository **Settings → Secrets and variables → Actions**.

Create these **Repository Secrets** (not ordinary variables):

| Secret name | Value |
|---|---|
| `YOUTUBE_CLIENT_ID` | OAuth Desktop client ID |
| `YOUTUBE_CLIENT_SECRET` | OAuth Desktop client secret |
| `YOUTUBE_REFRESH_TOKEN` | Refresh token created by the local script |

Create these **Repository Variables** (no secrets are needed for the values below):

| Variable | Safe initial value | Meaning |
|---|---|---|
| `DAILY_UPLOAD_ENABLED` | `false` | Main publishing kill switch. Must be explicitly `true` to upload. |
| `UPLOAD_PRIVACY` | `unlisted` | Initial visibility. Use `private`, `unlisted`, or `public`. |
| `CONTENT_NICHE` | `all` | `all`, or comma-separated categories such as `science,technology`. |
| `VIDEO_LANGUAGE` | `en` | YouTube metadata language. |
| `TIMEZONE` | `Asia/Kolkata` | Defines the daily idempotency date and summary. Use an IANA timezone. |
| `ALLOW_PUBLIC_UPLOADS` | `false` | Additional opt-in required when `UPLOAD_PRIVACY=public`. |

The workflow itself sets `DRY_RUN=false` on a scheduled run. For a manual run, the checkbox defaults to dry-run. To change the voice, add a variable `TTS_VOICE` (for example `en-us`) or edit the example/default in `config/settings.json`. A different script language requires selecting an appropriate installed voice and reviewing pronunciation/captions; changing YouTube metadata language alone does not translate narration.

## 5. First safe test, then unlisted publishing

1. Go to **Actions → Daily YouTube Short → Run workflow** and leave **Render and validate only** checked. This should create a video artifact, not upload anything.
2. Download the short-retention artifact and inspect narration, captions, source references, timing, claims, and visual quality. Captions are estimated from word duration and need review.
3. If rendering is good and Google OAuth has been fully configured, set `DAILY_UPLOAD_ENABLED=true` and keep `UPLOAD_PRIVACY=unlisted`. Run the workflow manually with dry-run **unchecked** to test the real upload. YouTube processing can take time after the API confirms insertion.
4. Verify the returned video URL in the job summary and check visibility in YouTube Studio. The API response and the saved video ID are the evidence of successful insertion; a local render is not an upload.
5. Only after repeated review should you change to public publishing. Set both `UPLOAD_PRIVACY=public` **and** `ALLOW_PUBLIC_UPLOADS=true`. This two-variable guard is deliberate.
6. Keep `DAILY_UPLOAD_ENABLED=true` to allow the scheduled workflow to publish. If it is false, the scheduled workflow can still render, but will not upload.

The scheduled time is `03:17 UTC` (08:47 in `Asia/Kolkata`). GitHub Actions cron uses UTC, may delay schedules during busy periods and is not guaranteed to run at the exact minute. GitHub may disable scheduled workflows in inactive repositories. Check the Actions page periodically.

## First-run checklist

- [ ] Push the repository to GitHub and keep the workflow on the default branch.
- [ ] Run `python -m pytest` and `python -m shorts_factory --dry-run`; review the MP4, captions, and `manifest.json`.
- [ ] Enable YouTube Data API v3, configure OAuth consent/client, and generate the refresh token locally.
- [ ] Add all three OAuth values under **Settings → Secrets and variables → Actions → Secrets**.
- [ ] Keep `DAILY_UPLOAD_ENABLED=false` while validating source quality and rendering.
- [ ] Set `DAILY_UPLOAD_ENABLED=true`, retain `UPLOAD_PRIVACY=unlisted`, and manually run with dry-run unchecked to verify the real upload.
- [ ] Only after editorial review and OAuth/API approval, opt into public visibility with both public-publishing variables.

## 6. Disable publishing immediately

Set repository variable `DAILY_UPLOAD_ENABLED=false` to stop uploads while leaving renders enabled. For a full stop, disable the workflow under **Actions** or remove/disable the schedule in `.github/workflows/daily-shorts.yml`. To revoke access, remove the OAuth credential in your Google Account's third-party access settings and/or disable the OAuth client/API in Cloud Console. Review both GitHub secret storage and Google access; simply deleting a local client JSON does not revoke an already-issued refresh token.

## 7. Configuration reference

| Setting | Default | Guard/behavior |
|---|---|---|
| `CONTENT_NICHE` | `all` | Must match topic categories or `all`; exhausted niches fail rather than reuse topics. |
| `VIDEO_LANGUAGE` | `en` | Used in YouTube metadata; not a translation engine. |
| `UPLOAD_PRIVACY` | `unlisted` | Public requires `ALLOW_PUBLIC_UPLOADS=true`. |
| `TIMEZONE` | `Asia/Kolkata` | Used for daily run marker; cron schedule itself remains UTC. |
| `DAILY_UPLOAD_ENABLED` | `false` | Upload off unless explicitly enabled. |
| `DRY_RUN` | `true` for local commands | Any forced dry-run blocks uploader code. Workflow manages it based on event/input. |
| `YOUTUBE_CLIENT_ID` | unset | GitHub Secret required for upload. |
| `YOUTUBE_CLIENT_SECRET` | unset | GitHub Secret required for upload. |
| `YOUTUBE_REFRESH_TOKEN` | unset | GitHub Secret required for upload. |
| `TTS_VOICE` | `en-us` | Must be installed/available in the local TTS engine. |
| `OUTPUT_DIR` | `build/output` | Local rendered media directory. |

Duration is configured in `config/settings.json` (default 50–60 seconds, hard maximum 180 seconds); measured narration is tuned toward 56 seconds, while the video validator remains the final gate. The workflow includes a finite five-minute rendering timeout, a 100 MB output cap, at most three upload retry attempts for a resumable chunk, five bounded topic-selection attempts, and bounded recent-upload scanning. Increase resource limits only after validating runtime and cost implications.

## 8. Tests and diagnostics

```bash
python -m pytest
python scripts/validate_environment.py
python -m shorts_factory --dry-run
```

Common failures:

- **Missing FFmpeg/libass:** install an FFmpeg build that includes `ffmpeg`, `ffprobe`, and the `subtitles` filter; inspect `ffmpeg -filters`.
- **Missing TTS or voice:** install `espeak-ng` and verify `espeak-ng --voices`; if that executable is absent locally, `espeak` is accepted as a development fallback. Set `TTS_VOICE` to a voice identifier present on the runner.
- **Duration outside 50–60 seconds:** the renderer fails closed. Review the narration pace and topic beat text; don't pad with silence merely to pass validation. Keep each beat's speech clear and captions aligned.
- **OAuth invalid_grant / expired refresh token:** re-check the consent screen status, account used, OAuth client ID/secret pairing, token age, scopes and revocation. Re-run the local consent flow as the owner if needed.
- **403 quotaExceeded:** wait for quota reset or request a legitimate quota review. Do not retry continuously. A typical daily quota allocation is limited and `videos.insert` has a substantial quota cost; check the live quota table for your project.
- **Private-only upload response/API restriction:** verify the project's YouTube API audit/verification status and current Google guidance. The system never attempts to bypass this policy.
- **No unused topics:** add new topic entries with unique IDs, seven meaningful beats, claim statements and source URLs from reviewed authoritative sources. `scripts/validate_environment.py` checks the source URL/domain structure but not claim truth.
- **Ambiguous upload failure:** the program scans recent channel uploads for the run marker and will not blindly start a second `videos.insert` after an uncertain result. Check YouTube Studio and the run marker before manually retrying.
- **Scheduled workflow did not run:** confirm the workflow is on the default branch, Actions are allowed, the repository has not had scheduling disabled due to inactivity, and the UTC cron is correct.

Tests that require a real Google account are intentionally not run in CI. The automated suite covers topic source metadata, duplicate checks, config gates, upload marker/privacy safety, workflow structure, and MP4 validation. A real upload test must be performed manually by the channel owner in `unlisted` mode.

## 9. Analytics

Run the optional snapshot command locally in an environment where the three OAuth variables are set:

```bash
python -m shorts_factory --stats
```

This stores timestamped video metadata, views and likes returned by `videos.list` in `data/analytics.json`. It is a point-in-time snapshot, not a full analytics product. The basic YouTube Data API endpoint does not supply revenue and audience-retention metrics here; do not infer those values. Audience-retention/engaged-view metrics, where available, require the relevant authorized YouTube Analytics API scope and endpoint, which is deliberately not bundled into the default OAuth flow. No engagement manipulation is performed.

## 10. Copyright, originality, and monetization

- All visual illustrations are drawn programmatically. No third-party footage, screenshots, stock imagery, or music is downloaded.
- The included source links are metadata, not proof of licensing or correctness. Read and verify sources before public release; cite sources in each video's description.
- Don't copy other creators' scripts, footage, narration or edits. Changing superficial visual elements is not meaningful originality.
- YouTube's [channel monetization policies](https://support.google.com/youtube/answer/1311392) can exclude repetitive/inauthentic, mass-produced or reused content even if the channel has enough views/subscribers. Programmatic generation alone is not a monetization strategy.
- YouTube's current [Shorts format guidance](https://support.google.com/youtube/answer/15424877) allows eligible square/vertical Shorts up to three minutes, but this project targets 50–60 seconds. Music and copyright rules can affect eligibility, especially for longer Shorts.
- Monetization also depends on current Partner Program eligibility, region/account standing and channel review. Check official policy pages periodically; platform policies and quota rules change.
